# 결정 기록

여러 파일에 걸친 선택과 그 이유를 적는다. 한 줄짜리 이유는 코드 주석에 있다. 새 결정은 아래에 같은 모양으로 더하고, 뒤집힌 결정은 고쳐 쓴다(남겨 두지 않는다).

각 항목은 **무엇**, **왜**, **하지 말 것** 순서다.

## 주인이 아직 정하지 않은 것

아래는 바꾸기 전에 주인에게 먼저 묻는다.

- **설치 위치.** README와 `docs/agent-install.md`는 `/Applications`라고 적지만, `Info.plist`의 Sparkle 설정 주석은 `~/Applications`를 전제한다(관리자 암호 없이 앱 안에서 교체). 어느 쪽이 맞는지 정해지지 않았다.
- **검색 순위.** 지금은 실행 횟수가 앞글자 일치보다 먼저다(`SearchViewModel.rankedApps`, 테스트 `testCurrentRuleUsageCountOutranksPrefixMatch`가 고정). 앞글자 일치를 먼저 두자는 제안이 있다.
- **윈도우 마그넷 설명.** README는 "왼쪽·오른쪽 절반"이라고 쓰지만 코드는 화면 너비의 20, 40, 60, 80, 100%를 차례로 돈다(`Constants.magnetSteps`). README와 코드 중 어느 쪽을 고칠지 정해지지 않았다.
- **`ClipboardManager` 같은 Manager 이름을 Store로 바꿀지.** 바꾸지 않은 상태다.
- 클립보드 기록을 개수(500)가 아니라 용량으로 자를지, 기록에 없는 이미지 파일을 정리할지. 손대지 않았다.

## 앱 전체

### 기본 격리는 MainActor (2026-11-10)
- 무엇: 프로젝트 설정 `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, Swift 5 모드. 백그라운드 큐에서 부르는 상태 없는 도우미만 `nonisolated`다(`LumenStorage`, `MemoryTrace`, `SecretStore`, `SleepPolicyService`, `DateParsers`, 일정 플러그인 id 확장).
- 왜: 거의 모든 코드가 UI다. 표시가 실제 쓰임과 맞아야 Swift 6 엄격 검사에서 진짜 문제만 남는다.
- 하지 말 것: 지금 Swift 6 모드로 올리지 않는다. `nonisolated` 타입의 static var는 `nonisolated(unsafe)`와 "어느 큐가 만지는지" 주석 없이 두지 않는다.

### 조립은 `AppDelegate`의 배열 하나 (2026-11-10)
- 무엇: 기능은 `AppDelegate`의 `features` 배열 순서대로 등록한다. 기능 고유의 시작 작업은 그 기능의 `setup()`에 둔다(손쉬운 사용 권한 요청은 `WindowMagnetFeature.setup()`).
- 왜: 배열이 곧 검색 목록과 메뉴 순서라 한눈에 보인다. 새 기능은 한 줄이면 된다.
- 하지 말 것: 스스로 등록하는 구조(정적 등록, 리플렉션)를 만들지 않는다.

### 단축키는 그 기능이 갖는다 (2026-11-10)
- 무엇: 기능 단축키는 각 기능의 `hotkeys`에 `kVK_*`로 적는다. 앱 전역 두 개(⌘Space, ⌘⇧L)만 `Core/Hotkeys/HotkeyDefinitions.swift`에 있다. `HotkeySpec`에는 설명 글이 없고, 라벨은 `HotkeyManager.describe`가 만든다.
- 왜: 기능을 지우거나 고칠 때 공용 파일을 건드리지 않게. 손으로 적은 설명은 아무도 읽지 않아 틀려도 몰랐다.
- 하지 말 것: 단축키 라벨을 문자열로 따로 적지 않는다.

### 단축키는 Carbon, 실패는 토스트 (2026-11-10)
- 무엇: `RegisterEventHotKey`로 등록한다. 등록 실패는 시작 때 토스트 한 번으로 알린다("⌘Space 단축키를 등록하지 못했어요…").
- 왜: 권한이 필요 없다. 실패해도 예외가 없어서, ⌘Space를 Spotlight가 쥐고 있으면 사용자는 "안 열린다"만 겪었다.
- 하지 말 것: 전역 단축키에 이벤트 탭(`CGEventTap`)을 쓰지 않는다. 입력 모니터링 권한이 필요해진다.

### 검색은 기능 타입을 모른다 (2026-11-10)
- 무엇: 켜고 끄는 기능의 추가 설정 줄은 `ToggleableFeature.detailAccessory`로 받는다.
- 왜: 검색이 `LidAwakeFeature`로 형 변환하던 자리였다. 다음 기능마다 같은 분기가 늘어난다.
- 하지 말 것: `Search/`에서 `as? 어떤Feature`로 분기하지 않는다.

### 패널은 한 번 만들어 계속 살려 둔다 (2026-11-10)
- 무엇: 패널과 뷰 모델은 처음 열 때 만들고 닫아도 해제하지 않는다. 닫힌 패널의 뷰 트리를 버리지도 않는다.
- 왜: 다시 열 때 빠르고, 노트의 커서와 실행 취소가 남는다. 메모리는 100MB 안팎으로 주인이 받아들였다.
- 하지 말 것: 메모리를 줄이려고 숨은 패널의 `contentView`를 버리는 변경을 주인에게 묻지 않고 하지 않는다.

### 정리는 `willHide()`, 모든 닫힘에서 (2026-11-10)
- 무엇: `KeyablePanel.orderOut`이 `onOrderOut`을 부르고, 컨트롤러가 거기에 `willHide()`를 건다.
- 왜: 설정 창이 뜨면 `AppDelegate`가 패널에 `orderOut`을 직접 부른다. `hide()`에서만 정리하면 이 경로에서 리소스 모니터가 5초 간격을 계속 돌았다.
- 하지 말 것: `willHide()`를 직접 부르거나 `hide()`만 닫히는 길이라고 가정하지 않는다.

### 토스트를 쓰고 알림 센터는 쓰지 않는다 (2026-11-10)
- 무엇: 사용자에게 알릴 것은 `LumenToast`로 띄운다.
- 왜: 알림 권한을 묻지 않아도 되고, 런처의 짧은 확인에 맞다.
- 하지 말 것: 결과가 화면에 이미 보이는 동작에까지 토스트를 붙이지 않는다.

### 로그인 항목은 시스템 상태를 그대로 읽는다 (2026-11-10)
- 무엇: `LoginItemManager.isEnabled`는 `SMAppService.mainApp.status == .enabled`다. 실패와 "승인 필요"는 토스트로 알린다.
- 왜: UserDefaults에 따로 적어 두면 시스템 설정에서 끈 뒤에도 메뉴에 체크가 남았다.
- 하지 말 것: 상태를 UserDefaults에 다시 복사하지 않는다. 예전 키 `launchAtLogin`은 사용자 설정에 남아 있지만 읽지 않는다.

### UserDefaults 키 규칙은 새 키에만 (2026-11-10)
- 무엇: 새 키는 `"<기능>.<이름>"`, 값을 가진 타입 안에 `private static let`. 규칙은 [architecture.md](architecture.md#저장).
- 왜: 키 모음 파일을 두면 기능마다 공용 파일을 고치게 된다.
- 하지 말 것: 지금 있는 키 이름을 바꾸지 않는다. 바꾸려면 옮기는 코드가 필요하고 사용자에게 얻는 것이 없다.

### 하지 않기로 한 구조 변경 (2026-11-10)
한 사람이 쓰는 1만 6천 줄 앱이라 아래는 비용이 이득보다 크다고 봤다. 다시 제안하지 않는다.
- Swift 패키지나 타깃을 나눠 의존 방향을 강제하기. 문서의 규칙으로 충분하다.
- 의존성 주입 컨테이너, `shared` 싱글턴을 프로토콜로 감싸기. 테스트가 필요한 곳은 이미 경로를 주입한다(`NotesViewModel(notesDir:)`, `AppIndexer(directories:)`, `SecretStore`의 `at:`).
- 기능이 자기 설정 탭을 내놓는 프로토콜. 설정 탭이 있는 기능이 클램쉘 모드 하나뿐이다.
- 패널 기능과 윈도우 컨트롤러를 합친 기반 클래스. 패널마다 키 처리가 달라 대부분 훅이 된다.
- `Search/`를 `Features/` 아래로 옮기기.
- Escape 처리를 기반 클래스로 모으기. 일정 패널은 팝오버가 떠 있으면 Escape를 양보해야 해서, 모으면 예외 장치가 필요하다.

## 저장

### `LumenStorage`가 경로와 JSON 입출력을 맡는다 (2026-11-10)
- 무엇: `Application Support/Lumen` 경로는 `LumenStorage`만 만든다. JSON은 `read`/`write`(atomic)로만. JSON이 아닌 형식(비밀 저장소, 노트 `.md`)만 직접 쓰고, 경로는 여기서 받는다.
- 왜: 정리(`retiredFiles`)와 옮기기가 한 곳에 모인다.
- 하지 말 것: `LumenStorage`에 상태를 두지 않는다. 백그라운드 큐에서 불린다.

### 비밀값은 Keychain이 아니라 파일 (2026-11-10)
- 무엇: `secrets.dat`에 기기 UUID로 XOR해서 저장하고 권한은 0600.
- 왜: 자가서명 빌드는 업데이트할 때마다 Keychain 접근을 다시 묻는다. 이것은 암호화가 아니라 가림이고, 위협 모델은 "파일이 노출돼도 토큰이 평문으로 보이지 않는다"에 그친다.
- 하지 말 것: 더 안전하다고 설명하지 않는다. 값을 로그에 남기지 않는다.

### `SecretStore`는 풀지 못한 파일을 덮지 않는다 (2026-11-10)
- 무엇: 파일이 없거나 비면 빈 사전, 있는데 못 풀면 nil이다. 값을 쓰기 전에 못 푼 파일을 `secrets.dat.bak-<초>`로 옮기고, 옮기지 못하면 쓰지 않는다. 지우기는 못 푼 파일을 그대로 둔다.
- 왜: 예전에는 못 푼 파일을 빈 사전으로 읽고 다음 저장에서 덮어 Jira 토큰이 모두 사라졌다. 키는 UUID를 한 번 못 읽어 대체 키를 쓰거나 홈 폴더를 다른 Mac으로 옮기면 바뀐다.
- 하지 말 것: `load`를 `?? [:]`로 "단순화"하지 않는다. 백업 파일을 자동으로 지우지 않는다.

### 옛 번역 기록 파일을 계속 읽는다 (2026-11-10)
- 무엇: 옛 파일에는 지금 없는 `pronunciation` 키가 있다. 일반 `Codable`이 모르는 키를 무시해서 읽힌다.
- 하지 말 것: 번역 기록 디코딩을 모르는 키에서 실패하는 방식으로 바꾸지 않는다. 테스트가 이를 고정한다.

### `AppItem.id`는 저장되는 값이다 (2026-11-10)
- 무엇: 번들 id, 없으면 경로. `AppIndexer.makeItem(at:)` 한 곳에서만 만든다.
- 왜: 실행 횟수(UserDefaults)와 숨긴 앱(`hidden_apps.json`)이 이 값으로 저장된다.
- 하지 말 것: id 만드는 법을 바꾸지 않는다.

## 기능별

### 클립보드 (2026-11-10)
- 비밀번호 관리자가 붙이는 `org.nspasteboard.ConcealedType`, `TransientType` 항목은 기록하지 않는다. 기록 파일은 0600. 이 규칙 전에 기록된 항목은 사용자 파일에 남아 있다.
- 항목은 이미지를 디코딩한 채 들고 있지 않고 PNG 경로만 갖는다. 복사할 때 메인 스레드는 바이트만 읽고, 변환과 쓰기는 `diskQueue`에서 한 뒤 메인에서 항목을 더한다. 쓰기가 실패하면 항목을 더하지 않는다.
- 중복 판정: 글은 본문 전체, 파일은 전체 경로로 비교하고 이미지는 합치지 않는다. 같은 이름의 다른 파일이 합쳐지고 새 이미지가 옛 이미지를 지우던 버그 때문이다.
- 기록에서 다시 복사할 때는 `ClipboardManager.copyToPasteboard(_:)`를 쓴다. 감시가 Lumen 자신의 쓰기를 새 항목으로 받지 않게 한다.
- 하지 말 것: `ClipboardItem`에 `NSImage` 필드를 다시 두지 않는다. `diskQueue`에서 `main.sync`를 부르지 않는다(`flushPendingSave()`가 반대로 기다려 멈춘다).

### 목록 선택은 id로 (2026-11-10)
- 무엇: 클립보드와 검색은 선택한 항목의 id를 들고 있다. 검색에서 사용자가 입력하지 않았는데 목록을 다시 만들 때는 `updateResults(keepSelection: true)`.
- 왜: 인덱스는 목록이 바뀌면 다른 항목을 가리켰다.

### 뷰는 값을 받는다 (2026-11-10)
- 무엇: 뷰 모델이 미리 만든 값(`ClipboardPreviewModel`, 검색의 앱 상세)을 뷰에 넘긴다. 뷰는 서비스를 부르지 않는다.
- 왜: 그릴 때마다 파일을 열거나 계산하던 곳이 있었다.

### 노트 (2026-11-10)
- 파일 입출력은 `NoteStore`의 직렬 큐 하나로만 한다. 지우기도 같은 큐라 늦게 도착한 쓰기가 지운 파일을 되살리지 않는다.
- 패널을 열 때마다 폴더를 다시 읽는다(외부 도구가 노트를 만들 수 있다). 메모리와 같으면 아무것도 바꾸지 않아 커서와 실행 취소가 남는다. 이번 실행에서 쓰기가 한 번이라도 실패했으면 다시 읽지 않는다(메모리가 더 새로울 수 있다).
- 하지 말 것: `flush()`에서 순서 파일을 무조건 다시 쓰지 않는다. 밖에서 바꾼 순서를 덮는다.

### 번역 (2026-11-10)
- 기록에는 보낸 글을 남긴다. 끝났을 때의 입력 칸 글이 아니다.
- 취소된 요청(⏎ 두 번)은 오류로 보이지 않는다. 판정은 `Task.isCancelled`로 한다. 번역 API가 취소 때 던지는 오류 타입을 확인하지 못했기 때문이다.

### 패널 아래 단축키 안내 (2026-11-10)
- 검색의 ⌘K("명령")와 ⌥⏎("실행") 안내는 지웠다. 무엇을 하려던 것인지 코드에도 문서에도 없었다.
- 번역의 ⌘C는 선택한 글이 없을 때 결과를 복사하고 토스트를 띄운다.
- 클립보드 삭제는 ⌘⌫다. 검색 칸에 늘 포커스가 있어서, 그냥 ⌫를 삭제로 쓰면 검색어를 지우려고 누르고 있을 때 기록이 지워진다.

### 리소스 모니터는 측정 횟수로 말한다 (2026-11-10)
- 무엇: 패널이 열려 있으면 5초, 닫혀 있으면 60초마다 잰다. 그래서 문구는 초가 아니라 횟수로 쓴다("6회 연속 초과", "직전 측정 대비"). CPU 기준은 `ResourceAnomalyDetector.cpuHighThreshold` 하나다.
- 하지 말 것: "30초 이상" 같은 시간 표현을 쓰지 않는다.

### 클램쉘 모드 (2026-11-10)
- sudoers 규칙(`/etc/sudoers.d/lumen`)으로 세 명령만 비밀번호 없이 허용한다. 켤 때마다 암호를 묻지 않기 위해서다. 상세는 `SleepPolicyService.swift` 주석.
- 켜는 것은 항상 사용자가 한다. 앱 시작 때 자동으로 켜지 않는다. 덮개를 닫고 가방에 넣으면 배터리와 발열 문제가 된다.
- Lumen이 켰다는 표시(`lidAwake.ownedByLumen`)가 있을 때만 끈다. 터미널에서 직접 켠 값은 건드리지 않는다.
- 켜져 있는 동안 5초마다 시스템 값을 `IOPMrootDomain`의 `SleepDisabled`에서 읽는다. `pmset -g` 프로세스는 그 속성이 없을 때만 띄운다.
- 자동 꺼짐 시각에 다른 작업 중이면(`isBusy`) 버리지 않고 60초 뒤 다시 시도한다.

### 일정 대시보드 (2026-11-10)
- **잘린 결과는 성공이 아니다.** 스토어가 `fetch` 결과를 그대로 캐시하므로, 페이지 중간이 깨지면 던진다.
- **Jira 부가 정보(스프린트, 에픽)**: 401, 429, 5xx, 네트워크 오류는 갱신을 실패시키고 나머지는 로그만 남긴다. 401을 삼켜 스프린트 없는 결과가 30분 캐시된 적이 있다. 보드나 에픽 타입이 없는 프로젝트가 어떤 상태 코드를 주는지 확인하지 못해서 나머지는 부드럽게 둔다.
- **강제 갱신 중복**: 조회가 이미 시작된 뒤 들어온 강제 갱신만 표시해 두고 끝난 뒤 한 번 더 받는다. Jira 설정 저장이 같은 순간에 두 번 부르기 때문이다. `running` 표시는 조회 작업이 스스로 지운다.
- **시계(`now`)**: 항목이 바뀔 때마다 바꾸지 않는다. 새 항목의 경계가 이미 지났을 때만 바꾼다. 깨어남, 날짜 바뀜, 시간대 바뀜, 타이머는 항상 바꾼다.
- **불러오는 중·오류 상태는 항목과 다른 프로퍼티에 둔다.** Observation은 저장 프로퍼티 단위로 추적해서, 한 사전에 두면 불러오기 표시가 바뀔 때마다 달력 전체가 다시 그려졌다.
- **`ScheduleItem.end`는 종일 항목에서 포함하는 마지막 날이다.** 하루 단위 계산은 `ScheduleItem.lastDay`를 쓴다. 자정에 끝나는 일정이 다음 날로 넘어가지 않는다.
- **항목 id는 출처의 중복 기준만큼 구체적이어야 한다.** 스프린트 id에 프로젝트 키, 캘린더 id에 캘린더 식별자를 넣는다. 겹치면 SwiftUI `ForEach` id가 겹친다.
- **팝오버 상태는 막대(`CalendarBarButton`)가 갖는다.** 주를 넘는 일정은 막대가 주마다 하나라, 부모가 상태를 가지면 두 막대가 상세를 함께 요청했다.
- **Jira 댓글은 최신 100개를 한 번에** 받아 오래된 순으로 보인다. 오래된 순으로 페이지를 넘기면 긴 글타래에서 최신 댓글이 잘렸다.
- **`JiraPlugin.setProjects`가 표시 여부를 갖는다.** 설정 탭은 키와 별칭만 넘긴다.
- 1.6 이전 설정을 옮기던 코드는 지웠다. v1.6.0부터 v1.6.9까지 모든 릴리즈에 들어 있었다.
